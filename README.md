# WinNetSwitch

WinNetSwitch — небольшое приложение для Windows 10/11, которое живёт в системном трее и позволяет управлять каждым **физическим** сетевым адаптером. Типичный сценарий — управлять Wi‑Fi и проводным Ethernet без открытия системных настроек.

## Как работает переключение

Приложение объединяет активные физические адаптеры из `Get-NetAdapter -Physical` с административно отключёнными PCI/USB сетевыми устройствами из Plug and Play (PnP). Поэтому Wi‑Fi остаётся в tray-списке даже после отключения и перезагрузки. Виртуальные адаптеры VPN, Hyper-V, WSL и других программ намеренно не показываются и не изменяются.

При щелчке по адаптеру WinNetSwitch меняет только его состояние и не трогает остальные адаптеры. Для включения:

1. если устройство административно отключено и исчезло из `Get-NetAdapter`, включает его через `Enable-PnpDevice`;
2. дожидается появления сетевого интерфейса;
3. для Wi‑Fi отдельно включает software radio через штатный Windows Native Wi-Fi API;
4. повторно проверяет итоговое состояние адаптера и Wi‑Fi radio.

При выключении Wi‑Fi приложение сначала выключает software radio, затем адаптер. Если операция завершается ошибкой после частичного изменения, WinNetSwitch пытается восстановить исходное состояние выбранного адаптера и показывает результат восстановления в уведомлении.

Windows WLAN API не может включить аппаратно выключенное радио. Если Wi‑Fi заблокирован режимом полёта, аппаратной кнопкой или политикой устройства, приложение сообщит об этом в ошибке и логе.

> Переключение физического адаптера разрывает текущие сетевые соединения, загрузки и удалённые сессии. Не используйте приложение для переключения адаптера, через который вы удалённо управляете компьютером. Включённый Wi‑Fi-адаптер не гарантирует подключение к точке доступа: выбор Wi‑Fi-сети остаётся за Windows.

## Требования

- Windows 10 версии 2004 (build 19041) или новее либо Windows 11;
- права локального администратора: Windows требует elevation для `Enable-NetAdapter` и `Disable-NetAdapter`;
- Windows PowerShell 5.1 и встроенный модуль `NetAdapter`;
- .NET 10 SDK только для сборки. Self-contained публикация не требует установленного .NET runtime.

Проект использует поддерживаемую LTS-версию .NET 10 и не содержит сторонних NuGet-зависимостей.

## Быстрый запуск

Скачайте или соберите `WinNetSwitch-Setup.exe`, запустите его и подтвердите UAC. Установщик:

- копирует self-contained приложение в `%LOCALAPPDATA%\Programs\WinNetSwitch`;
- добавляет ярлык в меню «Пуск»;
- регистрирует WinNetSwitch в разделе Windows «Установленные приложения»;
- создаёт elevated-задачу автозапуска при входе текущего пользователя;
- сразу запускает tray-приложение.

Удаление выполняется штатно через Windows «Установленные приложения»: деинсталлятор удаляет приложение, автозапуск, ярлык и диагностические логи.

Для сборки установщика откройте PowerShell в корне проекта:

```powershell
.\scripts\publish.ps1
```

Готовый пользовательский установщик находится здесь:

```text
artifacts\setup\win-x64\WinNetSwitch-Setup.exe
```

После установки отдельное окно приложения не открывается: значок появляется в системном трее. Если Windows скрыла значок, откройте область скрытых значков рядом с часами.

Щёлкните значок правой кнопкой и откройте подменю нужного адаптера. Галочка показывает включённое итоговое состояние; для Wi‑Fi она учитывает и состояние адаптера, и software radio. Команда `Включить` или `Выключить` меняет только выбранный адаптер. Команда `Включить только этот адаптер` включает выбранный и отключает все остальные; при ошибке приложение пытается вернуть исходное состояние всех адаптеров.

Обновление списка выполняется в фоне: во время него уже показанные адаптеры и их команды остаются доступны. Пока меню раскрыто, его пункты не пересоздаются и фокус не сбрасывается; новое состояние применяется после закрытия меню. Повторные изменения блокируются только на время фактического включения или выключения. Короткоживущий проверенный снимок списка устраняет лишний предварительный PowerShell-запрос при переключении, а итоговое состояние всё равно повторно проверяется через Windows. В меню также есть команды `Обновить` и `Выход`. Двойной щелчок по значку обновляет список.

## Диагностический лог

WinNetSwitch записывает запуск, обнаруженные адаптеры, запросы переключения, успешные результаты и полные исключения в UTF-8 лог:

```text
%LOCALAPPDATA%\WinNetSwitch\logs\WinNetSwitch.log
```

Открыть его можно прямо из tray-меню командой `Открыть лог ошибок`. При достижении 1 MiB текущий файл переносится в `WinNetSwitch.previous.log`, поэтому лог не растёт без ограничения. Ошибка записи лога не блокирует работу приложения.

## Разработка и проверка

В решении пять проектов:

- `src\WinNetSwitch.Core` — модели, безопасный PowerShell runner, Native Wi-Fi API и транзакционная логика одного адаптера;
- `src\WinNetSwitch.App` — Windows Forms `ApplicationContext`, `NotifyIcon` и меню без главной формы;
- `src\WinNetSwitch.Windows` — установка, деинсталляция, ярлык, uninstall registry и Task Scheduler autostart;
- `src\WinNetSwitch.Setup` — self-contained GUI-установщик со встроенным payload;
- `tests\WinNetSwitch.Tests` — исполняемые тесты без внешнего test framework.

Базовые команды:

```powershell
dotnet restore .\WinNetSwitch.slnx
dotnet build .\WinNetSwitch.slnx --configuration Release --no-restore
dotnet run --project .\tests\WinNetSwitch.Tests\WinNetSwitch.Tests.csproj --configuration Release --no-restore
```

Тесты используют только `FakePowerShellRunner` и `FakeWirelessRadioController`, не требуют прав администратора и не читают или меняют реальные сетевые адаптеры.

Полная Windows-проверка выполняет restore, Release-сборку, 15 автоматических тестов, self-contained публикацию приложения и setup, безопасное чтение реального списка физических/PnP-адаптеров и WLAN radio state через production service, нативный tray smoke-test (включая доступность меню во время фонового обновления) и проверку встроенного payload установщика:

```powershell
# Запустить из PowerShell с правами администратора.
.\scripts\verify.ps1
```

Если SDK установлен изолированно, путь к CLI можно передать без изменения системного `PATH`:

```powershell
.\scripts\verify.ps1 -DotNet C:\path\to\dotnet.exe
```

Adapter probe выполняет только чтение `Get-NetAdapter`, PnP и WLAN state, проверяет production JSON/parser/native-контракт и не меняет состояние сети. Smoke-режим создаёт нативные WinForms message loop, иконку, `NotifyIcon` и меню из встроенных fake-адаптеров, подтверждает отсутствие главной формы и завершает работу. Ни одна из этих проверок не включает и не выключает устройство или radio. Для CI без интерактивного рабочего стола можно пропустить обе Windows runtime-проверки:

```powershell
.\scripts\verify.ps1 -SkipSmoke
```

Для Windows on ARM публикация создаётся отдельно:

```powershell
.\scripts\publish.ps1 -Runtime win-arm64
```
